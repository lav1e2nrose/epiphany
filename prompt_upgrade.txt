你是一名顶级全栈工程师，同时具备医疗级软件的 UI/UX 设计审美。
你现在要从零构建一个名为 **"灵犀妙探"** 的 PC 桌面应用程序。

这不是网页，不是 demo，不是大学作业。
这是一款面向**家庭长程监测与临床诊断辅助**的医疗级癫痫管理平台，代码质量和视觉标准对标 $100,000 级别的医疗 SaaS 产品。

## PART -1 · 产品定位（v2 修订，必读）

> 本版本根据临床专家（郭老师，癫痫中心副主任医师）访谈反馈进行了重要定位调整。
> 设计与文案中**必须**贯彻以下定位，不可回退到泛化的"实时预警器"叙事。

### 核心定位
**家庭癫痫长程监测 + 诊断辅助 + 医患协作平台**

灵犀妙探不是一个简单的"实时报警器"。它解决的是临床上一个**未被满足的关键需求**：

> *"部分癫痫患者发作稀少，住院期间难以捕捉到发作。如果在家睡觉时佩戴头环，可对睡眠中的发作进行长程监测，结合视频形成'家庭简易脑电监测单元'，帮助医生发现发作事件、记录发作表现，回溯诊断。"*  — 郭老师

### 三层价值主张（按优先级）

1. **诊断辅助（最高优先级）**：在患者居家场景下捕获实际发作事件，提供原始 EEG + 症状描述 + 算法标注的可视化报告，作为医生临床决策的客观依据。
2. **家庭长程监测**：尤其是夜间睡眠监测 + 视频联动，弥补院内短时监测的盲区。
3. **辅助预警**：对已知患者，在可能发作前给出提示（次要价值，因为居家场景下医生无法实时响应，意义有限）。

### 设计含义
- **居家场景**：以**回顾性记录**为主，避免暗示"医生会立刻看到你的预警"
- **院内场景**（可选模式）：才适合强调实时预警
- 所有"预警"相关文案均需附带"事件已记录，将在下次复诊由医生回顾"等暗示

```typescript
  emgBurst: boolean

}
```

### 2.2 临床数据结构（v2 新增，必须实现）

> 根据郭老师反馈，临床上最有价值的信息是「发作三段式记录 + 既往史 + 诱因前驱症状」。
> 数据结构必须能承载完整的、结构化的临床信息。

```typescript
// src/types/clinical.ts

/** 既往病史 / 术前评估档案 */
export interface MedicalHistory {
  patientId: string

  // 既往史（郭老师明确要求的字段）
  cerebralInfection: BooleanWithDetail   // 脑炎/脑膜炎史
  headTrauma:        BooleanWithDetail   // 脑外伤史
  birthInjury:       BooleanWithDetail   // 出生时缺氧/产伤
  febrileSeizure:    BooleanWithDetail   // 热性惊厥史
  familyHistory:     BooleanWithDetail   // 癫痫家族史

  // 用药史
  medications: MedicationRecord[]        // 既往及当前用药
  drugReactions: string                  // 既往不良反应

  // 发作演变
  onsetAge: number                       // 首次发作年龄
  seizureFrequencyHistory: FrequencyPoint[]  // 历年发作频率变化
  seizureEvolutionNotes: string          // 发作演变文字描述

  // 检查资料
  examinations: ExamRecord[]             // EEG / MRI / PET-CT 报告与图片

  // 量表
  questionnaires: QuestionnaireResult[]  // 心理评估量表（QOLIE-31, BDI, NDDI-E等）

  updatedAt: number
  lockedByDoctor: boolean                // 医生锁定后患者不可改
}

export interface BooleanWithDetail {
  value: boolean | 'unknown'
  detail?: string                        // 例如"5岁时高烧抽搐，持续2分钟"
  ageAtEvent?: number
}

export interface MedicationRecord {
  drugName: string
  dosage: string
  startDate: string
  endDate?: string                       // 当前在服为 undefined
  effect: 'effective' | 'partial' | 'ineffective' | 'sideeffect'
  notes: string
}

export interface ExamRecord {
  type: 'EEG' | 'MRI' | 'CT' | 'PET-CT' | 'fMRI' | 'Video-EEG' | 'Other'
  date: string
  hospital: string
  conclusion: string
  attachments: { name: string; url: string }[]   // 本地文件路径或对象 URL
}

export interface QuestionnaireResult {
  name: string                          // 'QOLIE-31' | 'BDI' | 'NDDI-E' | ...
  date: string
  totalScore: number
  itemScores: Record<string, number>
  interpretation: string
}

/** 三段式发作事件（v2 重点：发作前/中/后必须分别记录） */
export interface SeizureEvent {
  id: string
  patientId: string

  // 基本信息
  timestamp: number                      // 发作开始时间
  durationSec: number
  source: 'algorithm' | 'patient' | 'guardian'   // 谁标记的
  confirmed: 'unconfirmed' | 'confirmed' | 'rejected'  // 医生复核状态

  // —— 发作前（最重要，郭老师反复强调）——
  pre: {
    triggers: TriggerRecord[]            // 结构化诱因（含 AI 追问结果）
    aura: AuraRecord[]                   // 前驱症状/先兆
    timeBeforeOnset: number              // 前驱症状出现到发作的间隔（秒）
  }

  // —— 发作中（症状表现）——
  ictal: {
    seizureType: SeizureType             // 发作类型
    symptoms: string[]                   // 结构化症状标签
    patientDescription: string           // 患者主观描述（如有意识）
    witnessDescription: string           // 旁观者/监护人描述
    videoClipUrl?: string                // 关联视频片段
    eegSnippetRef?: string               // 关联原始 EEG 片段 ID
  }

  // —— 发作后 ——
  post: {
    state: 'fully_recovered' | 'confused' | 'sleepy' | 'sore' | 'amnesia' | 'todds_paresis'
    recoveryDurationMin: number
    notes: string
  }

  // 当次用药依从性
  medicationCompliance: {
    missedDoseLast24h: boolean
    lastDoseTime?: number
  }

  // 医生侧字段
  doctorReview?: {
    doctorId: string
    reviewedAt: number
    annotation: string                   // 医生备注
    classification: SeizureType          // 医生认定的发作类型
    relevanceToTreatment: 'high' | 'medium' | 'low'
  }
}

export type SeizureType =
  | 'focal_aware'           // 局灶性意识清醒
  | 'focal_impaired'        // 局灶性意识障碍
  | 'focal_to_bilateral'    // 局灶性继发双侧强直阵挛
  | 'generalized_tonic_clonic'  // 全面性强直阵挛
  | 'absence'               // 失神
  | 'myoclonic'             // 肌阵挛
  | 'atonic'                // 失张力
  | 'unknown'

/** 诱因记录（含 AI 引导式追问） */
export interface TriggerRecord {
  category: TriggerCategory
  rawInput: string                       // 患者最初的语音/文字输入
  refinedAnswers: AIFollowUpAnswer[]     // AI 追问后的结构化回答
  severity: 1 | 2 | 3 | 4 | 5
}

export type TriggerCategory =
  | 'sleep_deprivation'    // 睡眠不足
  | 'emotional_stress'     // 情绪压力
  | 'missed_medication'    // 漏服药
  | 'alcohol'              // 饮酒
  | 'flashing_light'       // 闪光
  | 'fever'                // 发热
  | 'menstruation'         // 经期
  | 'fatigue'              // 劳累
  | 'other'

export interface AIFollowUpAnswer {
  question: string                       // AI 提出的追问
  answer: string                         // 患者回答（语音转文字 or 选项）
  answerType: 'voice' | 'text' | 'choice'
}

/** 前驱症状/先兆 */
export interface AuraRecord {
  type: AuraType
  description: string                    // 患者主观描述
}

export type AuraType =
  | 'epigastric_rising'    // 上腹部上升感
  | 'deja_vu'              // 似曾相识
  | 'jamais_vu'            // 似不相识
  | 'visual'               // 视觉异常（闪光、光斑）
  | 'auditory'             // 听觉异常（耳鸣、幻听）
  | 'olfactory'            // 嗅觉异常
  | 'gustatory'            // 味觉异常
  | 'somatosensory'        // 躯体感觉异常（麻木、刺痛）
  | 'autonomic'            // 自主神经症状（出汗、心慌）
  | 'fear_anxiety'         // 恐惧、焦虑感
  | 'unspecified'

/** 医患沟通消息 */
export interface ChatMessage {
  id: string
  patientId: string
  doctorId: string
  sender: 'patient' | 'doctor' | 'system'
  type: 'text' | 'voice' | 'image' | 'event_ref'  // event_ref=引用某次发作
  content: string
  attachments?: { type: string; url: string }[]
  refEventId?: string                    // 当 type=event_ref 时
  timestamp: number
  read: boolean
}

/** 医患通道控制（医生侧权限） */
export interface ChatChannel {
  patientId: string
  doctorId: string
  status: 'open' | 'closed' | 'readonly'  // 关键：医生可手动开关
  openedAt?: number
  closedAt?: number
  reason?: string                        // 关闭原因（如"已制定治疗方案"）
}

/** AI 智能小结 */
export interface AISummary {
  patientId: string
  periodStart: number
  periodEnd: number
  generatedAt: number
  modelVersion: string                   // 例如 "EpiNet-Summary-v1.2"
  highlights: string[]                   // 要点列表
  detectedPatterns: { pattern: string; confidence: number; suggestion: string }[]
  medicationAnalysis: string
  recommendations: string[]
  draftStatus: 'draft' | 'doctor_approved'  // 必须经医生确认后才能进入正式报告
}
```


**实现要求**：
1. **追问决策树**（hard-coded，但形式上像 AI）：
   - 关键词识别 → 命中诱因类别 → 进入对应追问流程
   - 每个 TriggerCategory 准备一套追问脚本（至少 3-5 个问题）
   - 示例：
     - 「睡眠不足」→ 追问就寝时间、起床时间、中途觉醒、入睡难易、白天补觉
     - 「情绪压力」→ 追问情绪类型（焦虑/愤怒/低落）、持续时长、触发事件、强度1-5
     - 「漏服药」→ 追问漏服的药物名、漏服时段（早/中/晚）、漏服天数
     - 「饮酒」→ 追问类型、量、时间
     - 「闪光」→ 追问来源（屏幕/阳光/灯光）、持续时长
     - 「发热」→ 追问体温、持续时间、是否服药
2. **每个问题至少提供 3 个快捷选项 + 语音/文字自由回答**（移动端友好，但桌面端同样支持）
3. **语音识别**：使用 Web Speech API，识别中文，识别失败时回退到文字输入
4. **可视化进度**：右上角"已记录维度 X / Y"
5. **结构化输出**：会话结束后自动生成 `TriggerRecord` 对象写入当前事件 / 生活日志

#### 5.3.2 三段式发作记录（关键）

当用户从实时动态页点击「记录症状」或主动选择「记录一次发作」时，进入**三段式表单流程**（步骤条 UI）：

```
[第 1 步 · 发作前]  →  [第 2 步 · 发作中]  →  [第 3 步 · 发作后]
   ●━━━━━━━━━━━━━━━━━━━━━━━━━━━━○━━━━━━━━━━━━━━━━━━━━━○
```

**第 1 步 · 发作前**
- 诱因（链接到 5.3.1 AI 追问流程）
- 前驱症状/先兆（AuraType 多选 chip）
  - 上腹部上升感
  - 似曾相识感（déjà vu）
  - 视觉异常（闪光、光斑、视野变化）
  - 听觉异常
  - 嗅觉/味觉异常
  - 麻木、刺痛
  - 心慌、出汗
  - 恐惧、焦虑
  - 其他（自由文本）
- 先兆出现到发作的间隔（秒数 / "不到 1 分钟" / "1-5 分钟" / "5 分钟以上"）
- 每个先兆类型选中后可补充文字描述

**第 2 步 · 发作中**
- 发作类型（SeizureType 单选，附图示）：
  - 局灶性意识清醒（部分性，意识保留）
  - 局灶性意识障碍（部分性，意识受损）
  - 局灶性继发双侧强直阵挛
  - 全面性强直阵挛（俗称"大发作"）
  - 失神（短暂愣神）
  - 肌阵挛（短暂抽动）
  - 失张力（突然瘫倒）
  - 不确定（让医生判断）
- 症状结构化标签（多选 chip）：
  - 意识丧失 / 意识模糊 / 意识清醒
  - 强直 / 阵挛 / 强直阵挛 / 自动症
  - 右上肢 / 左上肢 / 右下肢 / 左下肢 / 全身
  - 口角偏斜 / 凝视 / 双眼上翻
  - 失语 / 言语不清
  - 大小便失禁 / 舌咬伤
- 患者主观描述（如有意识，文本框）
- 旁观者描述（监护人填写，文本框）
- 关联视频（自动从监护人端视频联动调取）

**第 3 步 · 发作后**
- 发作后状态（单选）：
  - 完全恢复
  - 意识模糊（持续时间 _ 分钟）
  - 嗜睡 / 想睡
  - 肌肉酸痛
  - 记忆缺失
  - Todd 麻痹（一侧肢体无力）
- 恢复时长（分钟）
- 当日用药情况：过去 24h 是否漏服 / 上次服药时间
- 备注文本

**提交后**：生成完整 `SeizureEvent` 对象，标记为 `source: 'patient'`, `confirmed: 'unconfirmed'`，等待医生复核。

**关键功能（按郭老师要求实现）**：

1. **通道可控开关**（最重要的设计点）：
   - 每个患者一个独立通道，状态 open / closed / readonly
   - 右上角「关闭通道」按钮：弹出确认对话框，需选择/输入关闭原因（如"已制定治疗方案"、"已转诊"、"复诊后"）
   - 关闭后：患者端显示"通道关闭"提示，无法发送消息
   - readonly 状态：双方可查看历史消息但不可新增（用于过渡期）

2. **关联事件引用**：
   - 输入框旁「📎」按钮，弹出该患者的事件列表，选择一条作为消息附件
   - 消息中显示事件卡片，点击 → 跳转波形回溯页

3. **轻量级原则**：
   - 不支持音视频通话
   - 不支持已读回执（避免医生压力）
   - 不支持表情包（保持专业）
   - 支持文本、语音消息、图片

4. **批量管理**：
   - 列表顶部「批量关闭非活跃通道」按钮（30 天无消息的通道一键关闭）
   - 列表筛选：开放通道 / 已关闭通道 / 全部

5. **新消息通知**：
   - 患者档案中心、侧边栏均显示未读红点
   - 系统消息（如"患者完成档案锁定申请"）独立于聊天
